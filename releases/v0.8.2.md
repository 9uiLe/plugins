# Release Notes — v0.8.2

リリース日: 2026-10-02

## ハイライト

- **engineering-principles 0.3.0**: `maintainable-code` で Documentation / Comment を追加・変更するとき、技術的な意味を比喩・擬人化・評価語に置き換えず直接書くようになりました。判断基準、before / after の例、例外は `references/repository-coherence.md` に定義しています。
- Review では、責務・設計上の性質・設計理由が読み取れないなどの Impact を示せる場合だけ Finding にします。語調の好みだけによる指摘は false positive として出しません。

### Changed

- **engineering-principles**: `maintainable-code` の Documentation / Comment に、技術的な意味を比喩・擬人化・評価語へ置き換えず直接書く原則を追加。`principles.md` の「Documentation は Context を表す」に原則を置き、`repository-coherence.md` に判断基準（その表現が直接の記述で表せない技術的意味を持つか）、対象（装飾的な比喩、不要な擬人化、根拠のない評価語、内容のない修辞、曖昧な因果）、英語・日本語の before / after、例外（確立した技術用語、責務分析の語彙、Domain 用語、引用、技術仕様の説明を目的としない文章）を定義。Step 8 は追加・変更する文章だけに適用し、変更していない段落の書き換えは範囲外とする。Review では、責務・設計上の性質・設計理由が分からない、変更判断を誤る、などの Impact を示せる場合だけ Finding にし、語調の好みは false positive として除外する。`principles.md` の見出し「Test は仕様であり、在庫ではない」を「Test の数を品質としない」に変更。

## Compatibility / Migration

- スキル名、Workflow の Step 番号、Review の出力形式（Severity・Category・Finding・Evidence・Impact・Direction）と Category に変更はありません。engineering-principles を 0.3.0 へ更新して利用してください。
- 直接書く原則は Step 8 で追加・変更する文章だけに適用します。変更していない既存の段落は書き換え対象になりません。
- `references/principles.md` の見出し「Test は仕様であり、在庫ではない」を「Test の数を品質としない」に変更しました。旧見出しへのリンクや引用があれば更新してください。
- model-strategy 0.5.0、speakerdeck-knowledge 0.1.1、architecture-explainer 0.1.0 は変更なく継続提供します。
