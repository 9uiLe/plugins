# Release Notes — v0.8.1

リリース日: 2026-10-02

## ハイライト

- **engineering-principles 0.2.0**: `maintainable-code` で、public API・module の export・component 間 interface など、別の利用者・component が依存する contract boundary を設計・レビューできるようになりました。Workflow に API boundary の Step を追加し、boundary を扱う場合だけ `references/api-design.md` を読みます。
- Review に `API boundary` Category を追加しました。具体型・String・dependency・public symbol があることだけを理由にした指摘は false positive として出しません。

### Changed

- **engineering-principles**: `maintainable-code` に、別の利用者・component が依存する contract boundary（public API、module の export、component 間 interface、library API、domain / service boundary）の変更容易性を扱う `references/api-design.md` を追加。Workflow の Coupling と How の間に API boundary の Step を置き、boundary を追加・変更・レビューする場合だけ reference を読む。公開した How は consumer にとっての What になるという原則を `principles.md` に置き、Client API first、必要な capability だけの公開、representation と dependency を consumer へ伝播させないこと、call site の最適化、progressive disclosure、stringly-typed API、failure と cost semantics を言語に依存しない判断基準として定義。Review の Category に `API boundary` を追加し、具体型・String・dependency・getter・public symbol の有無だけを理由にした指摘を false positive として除外する。評価軸は増やさず、consumer への波及を Change locality に含めた。

## Compatibility / Migration

- スキル名と Review の出力形式（Severity・Category・Finding・Evidence・Impact・Direction）に破壊的変更はありません。engineering-principles を 0.2.0 へ更新して利用してください。
- `maintainable-code` の Workflow に API boundary を Step 6 として挿入したため、How 以降の Step 番号が 1 つずつ繰り下がります（How は Step 7、Repository coherence は Step 8、Simplification & validation は Step 9）。Step 番号で手順を指定している依頼文や運用手順があれば更新してください。
- Review の Finding の Category に `API boundary` が加わります。Category を集計・分類している場合は値を追加してください。
- model-strategy 0.5.0、speakerdeck-knowledge 0.1.1、architecture-explainer 0.1.0 は変更なく継続提供します。
