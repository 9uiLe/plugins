# Release Notes — v0.8.0

リリース日: 2026-10-02

## ハイライト

- **model-strategy 0.5.0**: route / audit の契約を明確化しました。`route` は mode に関係なく同じ形の結果を返し、`audit` は委譲マニフェストの `mode` / `modeSource` / `sessionModel` を必須とします（互換性に影響します。下記 Compatibility / Migration を参照）。
- **新規プラグイン 2 件**: 保守しやすいコード・テスト・責務境界を設計・レビューする **engineering-principles 0.1.0** と、コードから根拠を辿れるアーキテクチャ説明 HTML を作成・評価する **architecture-explainer 0.1.0** を Claude Code / Codex の両 marketplace に追加しました。
- **quality-architect を削除**し、リリース・検証ツールを整備しました（`release-prepare.sh` の CLI 変更、検証入口の `scripts/verify.sh` への一本化）。

### Added

- **engineering-principles** (v0.1.0): コード・テスト・ドメインモデル・責務境界を、仕様変更を局所的かつ安全にする観点で設計・レビュー・改善する `maintainable-code` スキルを Claude Code / Codex の両 marketplace に追加。Test で What、Code で How、Documentation で Context を表す原則のもと、What → State → Test responsibility → Responsibility → Coupling → How → Repository coherence → Simplification & validation の順に確認する。Implement / Review / Improve を依頼から判定し、Implement / Improve は会話履歴なしで Repository から現在仕様を理解できる状態を完了条件とする。Review は Severity・Category・Finding・Evidence・Impact・Direction の形式で実際の問題だけを報告する。Test 数・abstraction・コメント削除・Documentation の量・パターン準拠をそれ自体の改善とみなさない。
- **architecture-explainer** (v0.1.0): コードとアーキテクチャから、目的・構成・実行時の動き・コード・設計理由・変更影響を辿れる HTML 説明資料を作成し、既存資料をコードと照合して評価・改善するプラグインを Claude Code / Codex の両 marketplace に追加。HTML の前に Explanation Model を作り、claim を Observed / Inferred / Unknown に分けて file・symbol へ辿れるようにする。6 つの Hard Gate と評価次元による自己評価、構造・リンク・standalone・code ref を検査する validator を同梱。評価用の synthetic fixture と、その再構成・bug の再現を確かめる統合テスト、LLM 評価と表示確認の手順を追加。

### Changed

- **model-strategy**: `route-policy.mjs` の route / audit の契約を整理。`route` は mode に関係なく `{ rule, subtype, assignee: { claude, codex }, reasons }` を返し、conductor 以外では `subtype` が `null` になる。Codex 側の担当名をモデル名から `07-codex.md` の役割名 (`scout` / `implementer` / `main` / `judge`) に変更し、モデルと effort の対応は 07 だけに置く。`audit` は `mode` / `modeSource` / `sessionModel` を常に必須とし、`mode` を省略したマニフェストは `MISSING_MODE_FIELDS` になる (旧形式の免除により conductor の検査を回避できた状態を解消)。finding の error / warn 級は出力に存在しない文書上の区分だったため、文書と Test 名から削除。
- **release automation**: `release-prepare.sh` の 1 回のリリースで 0 件・1 件・複数件のプラグイン版を変更できるよう CLI を変更。**破壊的変更**: `--plugin <name> --bump <kind>` / `--version X.Y.Z` を、プラグインごとに繰り返す `--plugin <name>:<patch|minor|major|X.Y.Z>` に置き換え、`--plugin` を省略したリリースを可能にした。`--release-bump` と `--release-version` の同時指定（`patch` を含む）と同じプラグインの重複指定を拒否し、リリース版 ≥ リリース後の全プラグイン版の最大値を dry-run でも編集前に検査する。CHANGELOG の `[Unreleased]` 本文と直前のリリース版を編集前に一度だけ読み、CHANGELOG の繰り上げとリリースノート生成の両方へ渡すことで、dry-run と本番で同じ内容を生成する。dry-run は stage するファイルと PR 本文も表示する。`releases/vX.Y.Z.md` の既存チェックを編集前へ移し、ブランチ作成後・push 前の失敗では `die` や関数内の失敗・中断でも変更とブランチを必ず巻き戻すよう修正（従来は ERR trap に依存し、多くの失敗で半端なブランチと変更が残っていた）。version 一致検査と `release-prepare.sh` の受け入れテストを追加し CI で実行。`RELEASING.md` を新しい CLI と手順に更新。
- **repository verification**: CI とローカルの検証入口を `scripts/verify.sh` に一本化。ShellCheck、`verify-versions.sh`、README のプラグイン一覧の検査、`scripts/tests/*.test.sh`、`plugins/<name>/tests/` の Node.js / Python テストをファイル名の規約で発見して実行するため、テストの追加・削除で CI と CONTRIBUTING を更新する必要がない。workflow を `.github/workflows/verify.yml`（job 名 `verify` は維持）に改名し、検証対象がリポジトリ全体に及ぶため paths filter を外した。CONTRIBUTING に Pillow を含む必要ツールを明記し、RELEASING・各プラグイン README から repository 全体の検証コマンドの複製を除いた。プラグインの README と reference のコマンド例から、個人環境の wrapper `rtk proxy` を除いた。
- **plugin catalog**: 配布対象の正本を `.claude-plugin/marketplace.json` とし、ルート README のプラグイン一覧がこれと一致することを `scripts/verify-plugin-catalog.sh` で検査。Issue / PR テンプレート、CONTRIBUTING、README のインストール説明・リポジトリ構成からプラグイン名の列挙を除き、プラグインの追加・削除で更新する箇所を marketplace 2 件と README の一覧に限定した。
- **release automation**: `release-prepare.sh` の PR 作成を `forge gh pr-create` から `gh pr create` に変更し、`forge` への依存を削除。RELEASING の手順も `git` / `gh` だけで完結するよう更新。

### Removed

- **quality-architect**: プラグインを削除し、Claude Code / Codex の marketplace から除外。README、コントリビューション・リリース・セキュリティの各ガイド、Issue / PR テンプレートの参照を整理。

## Compatibility / Migration

### model-strategy 0.5.0（破壊的変更あり）

`scripts/route-policy.mjs` の `route` / `audit` を直接使う場合、またはその出力を読む仕組みがある場合は、次の変更に合わせてください。

- **委譲マニフェストの mode フィールドが必須**: `audit` に渡すマニフェストには、mode に関係なく `mode`（`conductor` | `judge-main`）・`modeSource`（`env` | `user-instruction` | `default`）・`sessionModel`（実際のセッションモデル名）が必要です。いずれかが欠落または enum 外の場合は finding `MISSING_MODE_FIELDS` になり、audit は PASS しません。0.4.x までは `mode` を省略したマニフェストが旧形式として扱われ、conductor の検査を回避できました。マニフェスト監査だけを使う場合も `"mode": "judge-main"` を記録してください。
- **`route` の戻り値を統一**: mode に関係なく次の形を返します。

  ```text
  { rule, subtype, assignee: { claude, codex }, reasons }
  ```

  `subtype` は conductor mode の R4 判定でだけ値を持ち、それ以外は `null` です。
- **Codex 側の担当名を役割名に変更**: `assignee.codex` はモデル名の略記ではなく、役割名 `scout` / `implementer` / `main` / `judge` を返します。役割とモデル・effort の対応は `references/07-codex.md` だけで定義します。
- finding の error / warn という区分を文書から削除しました。`audit` の出力形式自体は変わりません。

### Repository contributor tooling（破壊的変更あり）

リポジトリでリリースを準備する contributor に影響します。プラグインの利用者には影響しません。

- **`release-prepare.sh` の CLI を変更**: プラグイン版の指定方法を置き換えました。旧形式は使えません。

  | 旧 | 新 |
  | --- | --- |
  | `--plugin <name> --bump <patch\|minor\|major>` | `--plugin <name>:<patch\|minor\|major>` |
  | `--plugin <name> --version X.Y.Z` | `--plugin <name>:X.Y.Z` |

  複数プラグインの版を 1 回のリリースで変える場合は `--plugin` をプラグインごとに繰り返します。プラグイン版を変えないリリースでは `--plugin` を省略します。リリース版は `--release-bump` または `--release-version`（同時指定不可）で選びます。手順の正本は [`RELEASING.md`](../RELEASING.md) です。
- `release-prepare.sh` の PR 作成は `gh pr create` を使い、`forge` は不要になりました。
- **リポジトリ全体の検証入口は `bash scripts/verify.sh`** です。CI（`.github/workflows/verify.yml`、job 名 `verify`）も同じスクリプトを実行します。必要なツールは [`CONTRIBUTING.md`](../CONTRIBUTING.md) を参照してください。

### quality-architect の削除

quality-architect は提供を終了し、両 marketplace から除外しました。最終版は 0.1.5 で、以後の更新はありません。インストール済みの場合は削除してください。

```bash
/plugin uninstall quality-architect@9uile-plugins
```

```bash
codex plugin remove quality-architect@9uile-plugins
```
