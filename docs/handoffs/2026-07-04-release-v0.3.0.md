# 指示書: v0.3.0 リリース準備

## 0. 役割と絶対制約

あなたは 9uiLe/plugins リポジトリのリリース準備担当です。レビューと git/gh 操作は監督役 (Claude, Fable 5) が行います。

- この指示書と `RELEASING.md` (リリース手順の正本) が正典です。矛盾があれば停止して質問してください。
- git 操作 (branch / commit / push / tag) と gh 操作 (PR 作成・マージ・Release 作成) は一切禁止です。これらはすべて監督役が実行します。
- `scripts/release-prepare.sh` / `scripts/release-publish.sh` の本番実行は禁止です。M0 で実行してよいのは `--dry-run` 付きのみ。
- 不可逆操作・外部送信・公開設定の変更は禁止です。
- M0 ではファイル編集禁止。M1 で編集してよいのは `releases/v0.3.0.md` のみ。

## 1. 背景と正典リンク

- 目的: v0.2.0 以降に master へ入った変更をリリース版 v0.3.0 として出す。
- リリース対象 (`CHANGELOG.md` の `[Unreleased]`):
  - Changed: agent-ops スキル名を `codex-handoff` → `agent-handoff` にリネーム (breaking)
  - Fixed: agent-ops の Codex マーケットプレイスマニフェスト登録漏れ修正
  - Added: verify-versions.sh の Codex マニフェスト掲載チェック / agent-ops 委譲先の Claude Code / Codex 両対応化
- 正本: `RELEASING.md`。バージョンは二軸 (プラグイン版とリリース版 `metadata.version`)。整合性ゲート: `metadata.version >= max(プラグイン版)`。
- 監督役の作業仮説 (M0 で妥当性を検証し、問題があれば「確認が必要」に挙げること):
  - agent-ops: 0.2.0 → **0.3.0** (`--bump minor`。0.x 系では breaking 変更を minor で上げる運用)
  - リリース版: 0.2.0 → **0.3.0** (`--release-bump minor`)
  - 実行コマンド: `scripts/release-prepare.sh --plugin agent-ops --bump minor --release-bump minor`
  - 他プラグイン (tech-docs / quality-architect / model-strategy) は変更なしのため bump しない

## 9. M0 承認記録 (2026-07-04)

M0 は完了し、監督役が以下を回答・承認済み。

- バージョン: agent-ops 0.2.0 → 0.3.0 / リリース版 0.2.0 → 0.3.0 (`--bump minor --release-bump minor`) を承認。
- Q1 (forge 不在で dry-run 失敗) への回答: `--no-pr` を採用する。`forge` / `gh` の必須チェックは `--no-pr` 時に免除されることをスクリプトで確認済み。prepare の本番実行 (`--no-pr` 付き)・PR 作成・マージ・publish はすべて監督役が行う。dry-run は監督役が `--no-pr --dry-run` で実行し、差分プレビューを承認済み。
- Q2 (worktree clean 未検証) への回答: 監督役の preflight で master clean / origin 一致 / タグ未存在を確認済み。M1 でも git コマンドは `git status --short` (§7 の証拠取得) のみ許可する。
- ハイライト文案: 承認。
- **M1 スコープの拡張**: dry-run で雛形に TODO が 2 箇所あることが判明した (「## ハイライト」と「## Compatibility / Migration」)。本リリースは breaking (スキル名リネーム) を含むため、M1 では両方を記入すること。Compatibility / Migration には「旧名 `codex-handoff` でのスキル呼び出し・トリガーは新名 `agent-handoff` への読み替えが必要 (エイリアスなし)。その他の変更に移行作業はない」の趣旨を 1〜3 行で書く。
- 編集対象は引き続き `releases/v0.3.0.md` のみ。CHANGELOG・manifest 類は prepare スクリプトが書き換え済みのため触れない。
