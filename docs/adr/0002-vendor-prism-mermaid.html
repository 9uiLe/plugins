ADR-0002生成 HTML の Prism / Mermaid を CDN から vendor 同梱へ移行

tech-docs プラグインが生成する 1 枚 HTML から外部 CDN 参照を排除し、Prism / Mermaid をプラグインに同梱する。オフライン環境・IDE プレビュー・CSP 厳格環境での再現性を、CDN 依存というアンチパターンと引き換えに獲得する。

Context

tech-docs プラグインは ADR / 仕様書 / 汎用ドキュメントを 1 枚の自己完結型 HTML として生成する。装飾には Prism (シンタックスハイライト) と Mermaid (フロー図) を利用しており、これまでは cdnjs.cloudflare.com と cdn.jsdelivr.net から CDN 経由で読み込んでいた。

直前のブランチ fix/sri-on-cdn-templates では Subresource Integrity (SRI) ハッシュを追加することで、 CDN 経由スクリプトの改ざん検知を補強した。しかし議論の過程で次の前提が明らかになった:

  • 本プラグインの利用者は 公開 Web サイトに HTML をデプロイすることを主目的としていない。Git リポジトリ内 / ローカル file:// / IDE プレビュー / 社内 wiki への取り込み等が主な閲覧手段。
  • 本リポジトリは public であり、見ず知らずの第三者が /plugin install して使う。Plugin 作者は「install したら何もせず動く default」を提供する責務を負う。
  • ADR は 5〜10 年参照される長期成果物であり、URL の永続性に対する要求が一般の Web ページより高い。

これらの前提下では、CDN への依存は次のシナリオで装飾が機能しなくなる:

閲覧シナリオ CDN 構成 備考
オフライン / エアギャップ環境 外部到達不可能
VS Code / Cursor の HTML プレビュー Workspace Trust / CSP により外部 script をブロック
社内 Wiki / Confluence への取り込み サンドボックスが <script> を除去
5 年後の同じ HTML 再オープン CDN URL の長期可用性は保証されない
公開 Web デプロイ (Vercel / GitHub Pages) 動作する (が主用途ではない)

Decision Drivers

  • 柔軟性 / 設置性 (Installability): 第三者が install した瞬間、追加作業なしに装飾を含めて動作すること (ISO/IEC 25010:2023 §柔軟性)
  • 柔軟性 / 適応性 (Adaptability): オフライン・ローカル・IDE preview・CSP 厳格環境のいずれでも崩れないこと
  • セキュリティ / インテグリティ: 配布物の真正性が verify できること (SRI または同梱物の出所明示)
  • 保守性: 上流の重大 CVE に追従できる更新フローが存在すること
  • サプライチェーンの透明性: 何のバージョンが入っているかをリポジトリ単体で検証可能なこと

Considered Options

Option A — CDN + SRI ハッシュ (従来構成)

cdnjs / jsdelivr から Prism と Mermaid をロードし、integrity 属性で改ざんを検知する。プラグイン本体の配布サイズはゼロ。

Driver との適合: ❌ 設置性 (オフラインで装飾喪失) / ❌ 適応性 (CSP・IDE preview で動かない) / ◯ インテグリティ (SRI) / ◯ 保守性 (差し替え簡単)

Option B — vendor 同梱 (本案)

Prism コア + 必要言語コンポーネント + Prism テーマ + Mermaid を shared-assets/vendor/ 配下に commit し、 生成時に system/vendor/ へコピーする。HTML からの参照はすべて相対パス。

Driver との適合: ◯ 設置性 (どこでも動く) / ◯ 適応性 (CSP も OK) / ◯ インテグリティ (Git commit 自体が provenance、初回 commit 時に上流公式 SHA-512 と照合済み) / △ 保守性 (CVE 追従は手動だがバージョン pin の transparency と引き換え)

Option C — ハイブリッド (CDN 優先 + vendor フォールバック)

onerror ハンドラで CDN 取得失敗を検出し、ローカルへ切り替える。両方の利点を取りに行く構成。

Driver との適合: △ コード複雑度が増し、HTML が膨らむ。両系の検証コスト 2 倍。CSP 環境ではどのみち vendor のみで動くため、default を B にすればハイブリッドの存在意義が薄い。

Decision

✓

Option B — vendor 同梱を採用

shared-assets/vendor/ に Prism (コア + 言語コンポーネント + テーマ) と Mermaid を commit する。 すべての skeleton / sample / 出力 HTML は system/vendor/... の相対パスを参照し、外部 CDN への依存を排除する。 ISO/IEC 25010:2023 における設置性 (Installability) および適応性 (Adaptability) を重視した判断であり、 Twelve-Factor App Factor II 「Explicitly declare and isolate dependencies」(Wiggins, 2012) と整合する。

ハッシュは vendoring 時点で上流 (cdnjs / jsdelivr) が公開していた SRI ハッシュと完全一致を確認済み。 これにより vendor 配下のファイルが公式アーティファクトであることを transparency に担保する。

Consequences

Positive

  • オフライン / エアギャップ / 機内・出張中の閲覧で装飾を含めて動作する
  • VS Code・Cursor の HTML preview で図とコード装飾が機能する
  • CSP script-src 'self' 環境 (社内ポリシーの一般形) で動作する
  • 5〜10 年後の同じ HTML を開いても装飾が崩れない (URL 永続性に依存しない)
  • vendor 配下が Git の履歴に乗ることでサプライチェーンが 透明 (open design) になる (Saltzer & Schroeder 1975)
  • integrity / crossorigin 属性のメンテナンスから解放される

Negative

  • プラグイン配布サイズが +3.3 MB 増加 (Mermaid 3.2MB + Prism 約 50KB)。/plugin install 初回ダウンロード時間がわずかに伸びる
  • Prism / Mermaid の CVE / 機能追加に手動で追従する必要がある (上流リリースの監視は別途仕組み化が必要)
  • 各 ADR / spec / doc の出力ディレクトリに system/vendor/ がコピーされ、ディスク使用量が増える (同一ディレクトリ内では使い回し)

Neutral

  • SRI 属性が不要になり HTML 雛形が読みやすくなった (副次効果)
  • Google Fonts は引き続き CDN 読み込み (デザイントークン外、本 ADR の対象外)
  • 従来の CDN + SRI 構成は技術的には正しかったが、本プラグインのユースケースには適合しなかった

Compliance & Monitoring

  • CDN URL の混入禁止: shared-assets/templates/ および shared-assets/samples/ 配下に cdnjs.cloudflare.com / cdn.jsdelivr.net が現れないことを CI で grep チェックする。実装: .github/workflows/verify-vendor.yml ジョブ cdn-leak-check。
  • vendor 配下の継続的真正性検証: shared-assets/vendor/SHA256SUMS に各ファイルの SHA-256 を記録し、CI で shasum -a 256 -c SHA256SUMS を実行する。実装: .github/workflows/verify-vendor.yml ジョブ hash-verify。
  • vendor をレビューで埋もれさせない: .gitattributes で vendor/** を binary linguist-vendored 指定し、minified の文字列 diff を抑止する。
  • vendor アップグレード時の verify 手順: 上流公式の SHA-512 (cdnjs) / SHA-384 (jsdelivr) と再計算ハッシュの一致を確認 → vendor 差し替え → SHA256SUMS 再生成 → 本 ADR の「採用バージョン」表更新。詳細チェックリスト: .github/ISSUE_TEMPLATE/vendor_upgrade.yml。
  • CVE 追従: .github/workflows/vendor-upgrade-check.yml が四半期ごと (1/4/7/10 月 1 日) に npm の最新版を確認し、本 ADR に記載のバージョンと差分があれば自動で Issue を起票する。CVE は GitHub Advisories で prismjs / mermaid を別途チェックする。
  • vendor 配下の権限管理: 将来 maintainer が増えた段階で CODEOWNERS に /plugins/tech-docs/shared-assets/vendor/ @9uiLe を追記し、改変時のレビューを必須化する。
