# SpeakerDeck の取得と読解

取得の目的は、知識の根拠になるページ別本文と画像を揃えること。公開ページをブラウザ等で開き、タイトル・著者・日付・対象資料を確認する。ページ数は対象資料の本文ブロックや構造化データで確認し、おすすめ資料の情報と区別する。

## 取得補助の使い方

スキルディレクトリから実行する。実行環境が要求する場合は `rtk proxy` 等を付ける。

```bash
python3 scripts/fetch_deck.py 'https://speakerdeck.com/author/deck' --out /tmp/deck-source
python3 scripts/fetch_deck.py 'https://speakerdeck.com/author/deck' --out /tmp/deck-source --images all
```

Python 3 標準ライブラリと curl を使用する。`--images 5-12,19,24-29` で取得する画像を指定できる。画像 URL はページ内の実在するリンクから取得する。

| 出力 | 内容 |
| --- | --- |
| `source.html` | 取得または指定した元 HTML |
| `deck.json` | 書誌情報、ページ数とその根拠、ページ別本文・URL、画像 URL と取得状態 |
| `transcript.md` | ページ順に並べた読解用テキスト |
| `slide-NNN.jpg` / `.png` | 指定したページの画像 |

終了コードは成功が0、入力・本文取得・解析の失敗が1、画像の一部取得失敗が2。画像の失敗ページと理由は `deck.json` に記録する。既存の出力先が別資料を含む場合はエラーにする。同じ資料の再取得ではメタデータと取得対象ファイルを更新するため、取得範囲を独立して残す場合は別ディレクトリを使う。

`--html-file saved.html` は保存済み HTML を解析する。入力 URL と保存ページが同じ資料か確認する。画像取得を指定しない場合は通信しない。中間資料は一時ディレクトリで管理し、納品には知識の説明に必要な引用だけを含める。

## ページを読む

全ページの本文と画像を一巡し、論点とページの役割を把握する。コンタクトシートは俯瞰に使い、細かな文字・数値・コードは原寸画像で確認する。図解、比較、表、文字の少ないページ、段階表示は視覚的な根拠を確認する。本文が同じページでも、強調、矢印、配置の変化を読む。

取得済み、本文読了、画像俯瞰、画像精読を区別する。成果物には確認したページと精読範囲、未確認部分とその影響を記載する。表紙・経歴・反復ページも読解範囲に含めるが、独立した知識項目にする必要はない。

根拠へのページリンクは1始まりの `URL?slide=N` とする。既存クエリがある場合は適切に結合する。

## 取得できない場合

- HTTP エラーは応答と実行環境を確認し、公開ブラウザ閲覧など条件の異なる経路を選ぶ。同じ失敗の再試行には条件の変化を必要とし、ログインやパスワードを迂回しない。
- 本文を解析できない場合は、公開の画像や PDF の実在を確認する。推測した連番 URL は根拠に使わない。
- PDF はページ数と本文を抽出し、図をレンダリングして確認する。OCR を補助に使う場合は、否定・数値・コード・矢印の方向を画像と照合する。
- 本文も画像も読めない場合は PDF または画像の提供を求める。説明文や検索スニペットしか確認できていない場合、その範囲を明記し、全スライドを読解した資料として納品しない。
