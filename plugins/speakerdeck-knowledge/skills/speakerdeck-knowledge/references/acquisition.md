# 中間資料の取得と読解

知識の根拠となるページ別本文・画像・書誌情報を揃える。公開ページで対象資料、タイトル、著者、日付を確認する。本文の有無にかかわらず、ページ数と画像の順序を保持する。

## 保存先とコマンド

最終成果物の保存先は `SKILL.md` の規則に従う。取得補助の `--out` は中間資料専用の一時ディレクトリとし、`ai-knowledge/` や利用者が指定した成果物の保存先と分ける。

スキルディレクトリからのコマンド例。実行環境が要求する場合は `rtk proxy` 等を付ける。作業ディレクトリを移動しても、最終成果物の保存先の基準は実行開始時の場所とする。

```bash
python3 scripts/fetch_deck.py 'https://speakerdeck.com/author/deck' --out /tmp/deck-source
python3 scripts/fetch_deck.py 'https://speakerdeck.com/author/deck' --out /tmp/deck-source --images all
```

`--images 5-12,19` で画像の範囲を指定できる。`--html-file saved.html` は同じ URL の保存済み HTML を解析する。画像を指定しなければオフラインで動作する。

## 取得データの契約

| ファイル | 内容 |
| --- | --- |
| `source.html` | 取得または指定した元 HTML |
| `deck.json` | 書誌情報、取得日時、ページ数と根拠、ページ別の本文・リンク・画像取得状態 |
| `transcript.md` | ページ順の読解用テキスト。欠損本文には `[No text]` を表示 |
| `slide-NNN.jpg` / `.png` | 指定ページの取得画像 |

構造化データのページ位置と本文ブロックを対応付ける。欠落・重複・件数の不一致はエラーにする。構造化データにページ情報がない場合は、対象資料の本文ブロックの順序を使う。関連資料のページ数は混ぜない。

文字起こしの欠損リンクにある `None` は空の本文として扱い、画像リンクを保持する。通常の本文に含まれる `None` はそのまま残す。著者は構造化データ、次いで `og:author` を参照する。取得できない書誌情報は空欄とし、読解時に公開ページや表紙で確認する。

画像は本文ブロックの実在するリンクから取得し、JPEG/PNG の応答を保存する。各ページの状態は `not_requested`、`downloaded`、`failed` のいずれか。取得失敗時には理由を記録し、成功した画像を保持する。

終了コードは成功が0、入力・本文取得・解析・保存の失敗が1、画像の一部取得失敗が2。異なる資料がある保存先はエラーにする。同じ資料の再取得は取得対象のファイルを更新するため、取得範囲を独立して残す場合は別の一時ディレクトリを使う。

## 読解の進め方

全ページを一巡して論点とページの役割を把握する。本文がある場合はテキストと画像を照合し、欠損する場合は画像から読む。コンタクトシートは俯瞰に使い、細かな文字・数値・コードは原寸画像で確認する。図解、比較、表、文字の少ないページ、段階表示は、強調・矢印・配置の意味を確認する。

取得、本文読了、画像俯瞰、画像精読を区別して記録する。成果物には確認したページ、精読範囲、未確認部分とその影響を記載する。表紙・経歴・反復ページも読解範囲に含めるが、知識項目にする必要はない。

根拠のページリンクは1始まりの `URL?slide=N` とする。既存クエリは適切に結合する。最終成果物には説明に必要な引用を含め、中間資料一式を自動同梱しない。

## 取得できない場合

HTTP エラーでは応答と実行環境を確認し、公開ブラウザ閲覧など条件の異なる経路を選ぶ。同じ失敗の再試行には条件の変化を必要とし、認証を迂回しない。

本文を解析できなければ公開の画像や PDF の実在を確認する。PDF はページ数と本文を抽出し、図をレンダリングする。OCR を補助に使う場合は否定・数値・コード・矢印の方向を画像と照合する。推測した連番 URL でページを補わない。

本文も画像も読めない場合は PDF または画像の提供を求める。説明文や検索スニペットしか確認できていない場合はその範囲を明記し、全スライドの知識抽出として納品しない。
