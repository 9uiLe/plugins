# 画像を効率的に読む

目的は、根拠を確認するためにセッションへ入る画像の枚数・寸法・再読を抑えること。ファイルの JPEG 圧縮率やダウンロード量だけで token 削減を判断しない。実際の token 使用量はモデル・閲覧ツールに依存するため、削減率や固定の token 換算値は約束しない。

## 確認対象と読み方

1. 本文から「ページ・確認したい問い」を選ぶ。本文欠損や画像依存の内容は飛ばさず、画像主体の資料では少数ページずつ進める。全件を一度に開く必要はない。
2. 図のある位置や反復ページの判別だけが必要なら、小さなコンタクトシートを使う。読むページが既に決まっている場合は、単ページの縮小画像へ直接進む。全ページのシート閲覧を必須にしない。
3. 単ページの縮小画像で問いに答えられれば止める。文字・数値・コードが読めない場合は、元画像の必要領域を切り出す。矢印の両端や凡例など、意味を決める周囲も含める。切り出しでは関係が失われる場合だけ単ページの解像度を上げる。
4. 確認直後に一時ディレクトリの `reading-notes.md` へ、ページ・確認方法と領域・観察結果・未解決の問いを短く追記する。執筆、HTML 化、会話の圧縮後はこのメモを参照する。同じ画像は、新しい問いや可読性の問題がある場合だけ再度開く。

コンタクトシートで細かな文字を精読した扱いにしない。取得や縮小画像の生成だけでは閲覧済みにしない。本文のみで確認した範囲、画像で確認した範囲、未確認部分と影響を成果物へ記載し、未読部分を推測で補わない。

## ローカルで閲覧用画像を用意する

`scripts/prepare_images.py` は取得済みの `deck.json` と画像を使う。Python 3 と Pillow が必要。Pillow がなければ一時的な仮想環境など実行環境の通常の方法で用意する。追加できない場合は既存の画像処理ツールで同等の縮小・切り出しを行い、原寸画像の一括投入で代用しない。

スキルディレクトリからの例。必要ならコマンドに `rtk proxy` 等を付ける。

```bash
# 対象ページだけを追加取得。保存した本文と取得済み画像を再利用する
python3 scripts/fetch_deck.py 'https://speakerdeck.com/author/deck' --out /tmp/deck-source --html-file /tmp/deck-source/source.html --images 5-12,19
# 必要な単ページだけを縮小（長辺1280px以下、拡大なし）
python3 scripts/prepare_images.py --deck /tmp/deck-source/deck.json --pages 5,19
# 位置・構成の俯瞰が必要なときだけ。最大6ページずつ、長辺1280px以下
python3 scripts/prepare_images.py --deck /tmp/deck-source/deck.json --pages 5-12 --mode sheet
# 19ページ右半分を元画像から切り出す（左,上,右,下を0〜1で指定）
python3 scripts/prepare_images.py --deck /tmp/deck-source/deck.json --pages 19 --crop 0.5,0,1,1
```

出力は一時ディレクトリ内の `reading-images/`。標準出力にはパス・対象ページ・寸法だけを返すので、そのうち次の問いに必要な画像だけを画像閲覧ツールで開く。シートはページ番号を描画し、最大6ページで分割する。`--pages` は必須で `all` は受け付けない。`--max-edge` は必要時に256〜2048pxで調整できる。これはこの補助ツールの運用上の上限であり、モデルの仕様ではない。

同じ元画像・ページ指定・変換条件なら同じ出力を再利用する。ファイルの再利用とセッション内の再閲覧は別なので、既読かどうかはメモで判断する。元画像は変更せず、引用・配布には必要な元画像を使う。OCR が利用できる場合はローカルの補助抽出に使えるが、不確かな文字や視覚的関係は画像で確認する。

## 成果物と表示確認

HTML の data URI はローカルのコードで画像ファイルから埋め込み、base64・画像バイナリを会話やツールのテキスト結果へ出さない。埋め込み後の HTML 全文や巨大な diff も出さず、本文の確認は埋め込み前か画像データを除いた抽出で行う。

HTML の表示確認は代表的な PC ビューポートと、問題がある領域のスクリーンショットから始める。長いページの全面画像を繰り返し開かない。リンク・画像の有無・寸法・操作は DOM やブラウザの検査も使い、画像確認は可読性や配置の判断に使う。修正後は変更領域と影響範囲を確認する。
