# UI デザイン資料の検証

検証日: 2026-09-08。対象: `speakerdeck-knowledge` 0.1.0。

この検証は、公開スライドから作成した知識資料が、根拠・適用条件・行動・検証方法を備え、PC 向け HTML として読めることを確認する。対象は一つの公開資料であり、SpeakerDeck の全形式への対応や実案件での改善効果を保証するものではない。

出典は原 佑一『[いいUIとは？初心者向けに事例をもとにUIデザインを分解](https://speakerdeck.com/yuichi_hara7/ii-ui-toha-shoshinshamuke-ni-jirei-o-moto-ni-ui-dezain-o-bunkai)』。2026-08-29 公開、全30ページ。

| 成果物 | 内容 |
| --- | --- |
| [knowledge.md](knowledge.md) | 六つの知識、根拠と画像観察、適用条件・作業・検証・限界、経費申請の実践例、AI 作業指示 |
| [guide.html](guide.html) | 同じ知識を読む単体 HTML。原図4点、観察箇所の説明、応用表、手順、作業指示を掲載 |

## 取得と読解

公開 URL から curl を使って30ページの本文と30画像を取得した。画像の取得失敗は0件で、JSON-LD のページ数と本文ブロック数が一致した。取得コマンドはリポジトリルートから実行する。

```bash
rtk proxy python3 plugins/speakerdeck-knowledge/skills/speakerdeck-knowledge/scripts/fetch_deck.py \
  'https://speakerdeck.com/yuichi_hara7/ii-ui-toha-shoshinshamuke-ni-jirei-o-moto-ni-ui-dezain-o-bunkai' \
  --out /tmp/speakerdeck-knowledge-validation --images all
```

全ページの本文と画像の俯瞰を確認し、p.8・12・13・16・21・29 を原寸で精読した。三原則の紹介元注記と段階表示の強調の違いを画像で確認した。製品画面の小さな文字は全件精読していない。

取得した HTML・全文・画像一式は中間資料として管理する。共有 HTML には、説明の根拠となる p.8・12・21・29 の原図を出典付きで引用している。

## HTML の表示と操作

macOS の Chrome を Playwright から一時プロファイルで起動し、ローカルファイルを検証した。

| 項目 | 結果 |
| --- | --- |
| PC 表示 | 1440×900・1280×600 で横幅超過なし。ヘッダー、知識、原図、実践手順、作業指示の表示を確認 |
| ヘッダー | タイトルと説明、使う場面と用語、出典と公開情報を余白でグループ化 |
| 目次と凡例 | サイドバー幅360px、スクロール時に上端24pxで追従。目次の内部スクロールと凡例表示を確認 |
| セクション境界 | 目次に載る10節の隣接境界9箇所に区切り線を使用。節内とサイドバーに Divider なし |
| 原図 | 4画像が表示され、埋込データと取得済み原画像の SHA-256 が一致 |
| 拡大操作 | Enter でダイアログを開き、Esc で閉じ、起点のボタンへフォーカスが戻る |
| 内部リンク | 全10節と目次の順序が一致。キーボードで作業指示へ移動可能 |
| 作業指示 | 入力・受入条件・停止条件を常時表示。指示全文の開閉が動作 |
| JavaScript 無効 | 本文、原図、開閉できる指示全文を閲覧可能 |
| 外部依存 | 表示時の HTTP(S) リクエスト0件、スクリプト例外0件 |
| 印刷 | 印刷イベントで指示全文を展開し、サイドバーを非表示にする |

印刷 PDF 全ページの目視校正、他のブラウザ、スクリーンリーダーでの実機検証は未実施。スマートフォンは対象外。

## 自動検証と再実行

リポジトリルートから実行する。

```bash
rtk proxy python3 -m unittest discover -s plugins/speakerdeck-knowledge/tests -v
rtk proxy bash scripts/verify-versions.sh
rtk git diff --check
```

取得処理のテストは11件成功。本文と画像のページ対応、欠落・重複・不一致の拒否、オフライン CLI、別資料の上書き防止、画像取得の一部失敗時の保存、画像以外の応答の拒否、本文欠損と通常の文字列 `None` の区別、著者情報の補完を確認した。取得済みの元 HTML でも30ページの解析を確認した。

skill-creator の `quick_validate.py` と plugin-creator の `validate_plugin.py` は成功。バージョン検証では、両環境の登録・パス・バージョンの整合性を確認した。

ローカルアプリへのインストールと外部公開は検証範囲に含めない。
