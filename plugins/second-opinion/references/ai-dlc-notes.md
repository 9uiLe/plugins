# AI-DLC findings for decision councils

Reviewed `aws-samples/sample-collaborative-ai-dlc` at commit [`8b8168d`](https://github.com/aws-samples/sample-collaborative-ai-dlc/tree/8b8168d8b25302487722e5fa336295262b13f8f8) on 2026-07-15. This is an implementation sample, not evidence that any specific model or council topology is universally superior.

## Transferable mechanisms

- **Remove ambiguity before execution.** Inception asks structured clarification questions before generating requirements, stories, and tasks. Decision Council adopts this as its evidence-readiness gate, not as permission to let advisors fill factual gaps. [Inception](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/concepts/inception.md)
- **Default to asking, but bound the loop.** The agent rules explicitly describe overconfidence/under-questioning as a failure, require follow-up on ambiguous or contradictory answers, and bound repeated clarification before asking the human to confirm the best current understanding. This supports a strict readiness gate plus an escape from endless questioning. [Overconfidence prevention](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/lambda/agents-ecs/aidlc-rules/aws-aidlc-rule-details/common/overconfidence-prevention.md), [Question format guide](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/lambda/agents-ecs/aidlc-rules/aws-aidlc-rule-details/common/question-format-guide.md)
- **Connect intent to downstream work.** The platform links requirements, tasks, and code in a graph so changes can be traced. Decision Council uses a lightweight evidence-ID and recommendation-disposition ledger rather than requiring a graph database. [README](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/README.md), [Methodology](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/getting-started/methodology.md)
- **Separate lifecycle roles.** The sample distinguishes Inception, Construction, Review, and Modify agents. This supports separating research, decision synthesis, implementation, and verification rather than letting one advisor both recommend and execute. [Methodology](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/getting-started/methodology.md)
- **Ask rather than guess.** Construction pauses for ambiguous implementation choices. Decision Council escalates decision-changing unknowns instead of manufacturing consensus. [Construction](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/concepts/construction.md)
- **Use complementary reviews and preserve human authority.** The implemented prompts use a code-only technical reviewer that must not read the sprint graph and a full-graph business reviewer; then a human makes the final pass/fail decision. Decision Council similarly preserves independent first-round views and keeps final authority with the accountable decision owner. The review documentation describes blindness differently, so the code prompt is the authoritative implementation evidence. [Review prompt builders](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/lambda/agents-ecs/pool-worker.js), [Review documentation](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/concepts/review.md)
- **Persist resolution, not only chat.** Discussion threads can store a resolution summary and accepted outcome, and later agents consult those decisions. Decision Council's final record captures rationale, dissent, unknowns, and reconsideration triggers. [Discussions](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/using-the-platform/discussions.md)
- **Make refinement iterative and criterion-based.** Rejected work returns with structured criteria and history. Decision Council uses a discriminating-test challenge and explicit dispositions rather than a free-form argument loop. [Reviewing work](https://github.com/aws-samples/sample-collaborative-ai-dlc/blob/8b8168d8b25302487722e5fa336295262b13f8f8/docs/using-the-platform/reviewing-work.md)

## What not to infer

The repository does not establish an optimal choice among Fable, Codex, or another model; minimum effort; chair topology; statistical independence; or that two-agent review is sufficient for every decision. Those require current provider documentation and task-specific calibration. Its graph database, AWS services, real-time collaboration, and task DAG are platform implementation choices, not prerequisites for the portable skill.

The platform abstracts Claude, Kiro, and OpenCode behind drivers, but one driver handles a run; this is host portability, not a multi-model debate implementation. [Agent drivers](https://github.com/aws-samples/sample-collaborative-ai-dlc/tree/8b8168d8b25302487722e5fa336295262b13f8f8/lambda/agents-ecs/drivers)
