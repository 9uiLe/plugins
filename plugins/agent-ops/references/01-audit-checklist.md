# 懐疑的監査チェックリスト

委譲先の成果物を受け入れる前に、以下を確認する。

- [ ] **自己報告を独立検証した**
  委譲先が「テスト通過」と報告しても、受け入れ条件のコマンドを自分で再実行する。自己報告は成果物ではなく、検証ログだけが証拠である。

- [ ] **独自設計判断を探索した**
  指示書・正典にない設計判断を diff から特定し、最優先で疑う。委譲先が独自導入した pass-through 設計に欠陥が複数あり、既存テストがそれを検出できなかった失敗を一般化した項目である。

- [ ] **否定的証明に対照群を置いた**
  「参照が残っていないこと」を grep/rg で確認する場合、検出できるはずの対照ケースで同じ手法がヒットすることを先に確認する。`rg` はバイナリを黙ってスキップするため、`no matches` は消去の証明にならない。

- [ ] **視覚成果物を直接確認した**
  UI 変更はスクリーンショット・録画を自分の目で確認する。委譲先の「問題は極端な条件のみ」という楽観報告が、実際には静止状態でも視認できる欠陥だった失敗を一般化した項目である。

- [ ] **クリーンアップを確認した**
  一時ファイル・実験ファイルの残存、import 漏れ (新規ファイル追加時のビルド確認) をチェックする。並列・委譲実装の後に実験用ファイルが残存し、新規テストファイルの import 漏れでビルドが壊れた失敗を一般化した項目である。

- [ ] **スコープ遵守を確認した**
  diff が指示書のスコープ内に収まっているか確認する。スコープ外の変更は理由を確認し、原則差し戻す。

- [ ] **ゲート自体の健全性を疑った**
  受け入れ条件の閾値・ゲートが形骸化していないかを定期的に疑う。誤った閾値が有効な変更を捨てさせ続けた失敗を一般化した項目である。

- [ ] **指摘に「指示書起因」タグを付けた**
  各指摘について「指示書に書いてあれば防げたか」を判定する。独自設計判断・エスカレーションはすべて指示書の穴のシグナルであり、起因タグ付きで振り返り台帳 (04-retrospective-ledger.md) に回す。
