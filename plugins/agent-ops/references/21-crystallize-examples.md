# 資産化例

履歴由来の知見を公開リポジトリ向けに一般化した例である。個別アプリ名や非公開の識別子は含めない。

1. **ドキュメントの表記矯正**
   知見: 区切り線の乱用禁止は、口頭指摘だけでは再発する。
   資産化: lint スクリプトと規約文書 1 行に落とす。
   効果: レビュー前に自動検出できる。

2. **実機ベースライン測定が手作業で面倒**
   知見: 「面倒」と感じる測定は、反復時に省略されやすい。
   資産化: 測定を全自動化するスクリプトを新規作成する。
   効果: 同一条件の before/after を再取得しやすくなる。

3. **不安定な perf ゲートの誤判定**
   知見: 絶対値ゲートは環境ドリフトで偽 FAIL を出す。
   資産化: A/B 同条件デルタ判定へ昇格する。
   効果: 変更起因の差分と環境要因を分離できる。

4. **アーキテクチャ違反の再発**
   知見: 依存方向の違反は、設計文書だけでは再発する。
   資産化: 依存方向を検査するスクリプトを追加する。
   効果: 設計判断を回帰テストとして仕組み化できる。

5. **委譲・監査・評価ループの反復**
   知見: 委譲・監査・評価の手順は複数プロジェクトで繰り返された。
   資産化: 本プラグイン (`agent-ops`) としてスキルと reference に分ける。
   効果: 常駐コンテキストを増やさず、必要時に pull できる。
