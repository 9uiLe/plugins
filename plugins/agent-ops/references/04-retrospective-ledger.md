# 振り返りと台帳

委譲 1 件を締めるたびに記録する。目的は、監督役・Fable・ゲートが補った観点を蓄積してテンプレートへ還流し、「無知の無知」を既知のチェック項目に変換すること。

## 状態ヘッダ (台帳ファイル先頭)

台帳ファイルの先頭に置き、監督役が委譲 1 件を締めるたびに更新する。運用モードの判定 (06-operating-protocol.md) はこのヘッダだけを入力とする。

```markdown
# ハンドオフ台帳

- フェーズ: 1 (Fable 著者) / 2 (自分著者 + Fable 批評) / 3 (自分著者)
- ベースライン記録: N 件 (フェーズ 1 の Fable 著者タスクで加算)
- 前回 Fable-off からのタスク数: N (5 に達したら次の委譲は Fable-off 訓練)
```

## 記録フォーマット (4 行 + 4 指標)

```markdown
## <日付> <作業名> (著者: 自分 / Fable / 自分+批評)

- 最初の自分の依頼に足りなかった情報:
- ゲート・批評・Fable が補った観点:
- 実行側が失敗しかけた点:
- 次回からテンプレートに入れるべき項目:

指標: ゲート質問数 N / エスカレーション N / 指示書起因の監査指摘 N / 一発受け入れ 可否
```

## 4 指標の定義

| 指標 | 定義 |
| --- | --- |
| ゲート質問数 | 着手前ゲート M0 で出た「確認が必要」の件数 |
| エスカレーション数 | M1 以降、作業中に委譲先が停止して質問した件数 |
| 指示書起因の監査指摘数 | 監査指摘のうち「指示書に書いてあれば防げた」もの (監査時に起因タグを付ける) |
| 一発受け入れ | 差し戻しなしで受け入れたか |

ゲート質問数と指示書起因指摘数の減少傾向が「無知の無知が既知化している」直接の証拠であり、05-fable-independence.md のフェーズ移行判定の入力になる。

## 置き場

- 台帳は委譲を行うプロジェクト側の `docs/handoff-ledger.md` に追記する。
- 指示書本体もリポジトリに残し、事後に穴の注記ができるようにする。
- 置き場は pull 型を維持する。AGENTS.md / CLAUDE.md 等の常駐コンテキストには流さない。

## テンプレートへの還流

「次回からテンプレートに入れるべき項目」が 2 回現れたら、crystallize のフローで `00-handoff-template.md` の「書き方」へチェック項目として一般化する。発火テストとして、わざとその項目が欠けた指示書を着手前ゲートに通し、質問として検出されることを確認する。
