# 運用プロトコル (監督役の自動進行)

このスキルの手順はユーザーに記憶させない。ユーザーが覚えるのはトリガーフレーズ (「外部エージェントに作業させて」等) だけであり、発火した監督役セッションが状態を読み、毎ステップで次の行動を提示する。

## 発火直後 (ステップ 0)

1. 対象プロジェクトの `docs/handoff-ledger.md` を読む。存在しなければ状態ヘッダ付きで新規作成する (フェーズ 1 / ベースライン 0 件 / Fable-off カウンタ 0)。
2. 状態ヘッダから今回の運用モードを判定し、**最初の応答で宣言する**:
   - Fable-off カウンタが 5 に達している → **Fable-off 訓練**。著者 = ユーザー、批評 = アンサンブル。監督役モデルを Opus 系へ切り替えるようユーザーに案内する (Fable を使わないこと自体が訓練)。
   - フェーズ 1 → 監督役 (Fable) が著者。ただし先にユーザーの粗いドラフトを受け取る (差分採掘のため。ドラフトなしで書き始めない)。
   - フェーズ 2 → ユーザーが著者、監督役は批評のみ。
   - フェーズ 3 → ユーザーが著者、監督役はゲートで残った質問への回答と監査のみ。
3. ユーザーに聞くのは 4 点だけ: **目的 / 困っていること / 理想 / 制約**。それ以上の完成度を求めない。

## 進行中の責務

- 各ステップ完了時に、次のステップと「ユーザーがやること」を 1〜2 行で提示する。ユーザーがフローを覚えている前提で進めない。
- 批評・実行セッションの起動が必要な場面では、**コピペ可能なコマンドとプロンプト**を提示する (批評は 03-preflight-gate.md の定型、実行経路は委譲先に応じて 02-execution-claude.md または 02-execution-codex.md)。
- 批評セッションには指示書ファイルのパスだけを渡させる。この会話の文脈を貼らせない (コンテキスト分離が壊れる)。
- M0 の「確認が必要」が残っている間は、M1 承認に進む選択肢を提示しない。

## 締め (ステップ 7 の自動化)

委譲 1 件を締めるとき、監督役が行う:

1. 台帳エントリ (4 行 + 4 指標) を書く。
2. 状態ヘッダを更新する: Fable-off カウンタ +1 (Fable-off 実施時は 0 にリセット)、フェーズ 1 でのベースライン件数を加算。
3. Fable を使ったのに台帳に残滓 (差分・批評・質問パターン) がゼロの場合、締めを完了せず採掘漏れとして指摘する。
4. 「次回からテンプレートに入れるべき項目」が 2 回目の出現なら、crystallize による還流 (plugins リポジトリへの変更) を提案する。
5. 05-fable-independence.md のフェーズ移行判定に該当したら、移行を提案する。ユーザーが判定条件を覚えておく必要はない。

## Codex を監督役にする場合

このプロトコルは `.codex-plugin` 経由で Codex からも読める。Fable-off 訓練や Fable 喪失後は、Claude Code (Opus) または Codex の監督セッションが同じプロトコルで進行する。
