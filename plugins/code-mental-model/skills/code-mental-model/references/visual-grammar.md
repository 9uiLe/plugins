# System Mental Model Map の visual grammar

HTML の固定 assets と renderer を変更するときに読む。**形 = 対象の種類、線 = 関係、色 = 現在の注意対象**を基本とする。色に複数の意味を持たせず、装飾目的のカードやグラフを増やさない。Agent は生成ごとにこの規則を再実装しない。デザイン変更は `assets/` と `scripts/render_html.py` に反映し、再生成する。

## 第一画面

タイトルと短い要約の直後に、ページで最も面積の大きい System Mental Model Map を置く。凡例は図の近くに置き、図を読む前に長い用語集を要求しない。読者がまず見つけるのは主要オブジェクト、接続、変更点。目次は広い画面の左サイドバーで追従できる。狭い画面では本文幅と図の可読性を優先して配置を変える。

Map は実際の関係をたどる canvas とする。固定 renderer が desktop / mobile の inline SVG を描き、viewBox、`<title>` と `<desc>`、意味のある link を付ける。長い edge label は固定ルールで短縮し、完全な operation と data は選択詳細に置く。説明文は図の外側に置く。node と edge は hover / focus と、キーボードで使えるアンカーを持つ。

## 表現の例

| 意味 | 色以外の手掛かり |
| --- | --- |
| application object / domain object | 角丸長方形 / 文書形など、用途が異なる輪郭。種類によってアクセント色を変えない |
| 状態の所有者 | 二重枠と役割文言 |
| 外部システム・副作用 | 六角形と役割文言。変更色を流用しない |
| 確認済み / 推論 / 未確認 | 実線 / 破線と、選択詳細の `Confirmed` / `Inferred` / `Unknown` |
| 呼び出し / 戻りデータ | 実線矢印、向きと動詞ラベル。戻りは別レーンや異なる矢印パターン |
| 外部境界 | 六角形の node と役割文言。接続は方向付きの edge で示す |
| added / removed / changed / existing | `+` / `−` / `Δ` / 無印と線種・ラベル。削除は現在の経路に見せない |
| 選択中の実行経路 | 太い線と edge 上の順番。別経路の node/edge は表示しない |

これは固定の図形規格ではない。同じページで意味を変えず、凡例と実際の図を照合する。例えば緑を Added に割り当てたらデータ型の色にはしない。琥珀を Changed に割り当てたら外部システムの色にはしない。selection accent は Added / Changed / Unknown / Failure と別に定め、Map の対象と Code Lens の対応行にだけ共通して使う。色は小さい面積と十分なコントラストで用い、見分けを色だけに依存させない。Unknown は実体を断定した形にしない。

## Layout

`layout_engine.py` は roleCode による理解順序を軸に固定順序の候補を生成し、`readability.py` が交差・重なり・ラベル衝突・往復の曖昧さ・線長・折れを固定重みで測る。衝突のある候補を退け、最小コストと候補 ID の順で選ぶ。同じ model は同じ評価値・座標・HTML になる。主図へ情報を詰め込まず、詳細 class・例外経路・コード断片は node/edge の選択先へ送る。重要なデータと状態は隠さない。

Overview では Map に面積を渡し、Code Lens は隠す。Focus では Map を残したまま、図の直下に全幅 Code Dock を置く。選択名→短い意味→コードの順に近接させる。狭い floating Inspector にコードを置かない。Mobile は別の決定論的レイアウトを使い、主要な関係ラベルを残す。図の周囲だけでなく、ノード名・線ラベル・条件の**実際に描画された**文字サイズを確認する。全体のページ幅は保つ。印刷では主図・凡例・選択に依存しない関係の説明が残るようにする。

## 表示モードと詳細

Structure / Execution / Change は node と edge の ID を共通にする。Structure は中立の主要接続、Execution は選択したシナリオの node・edge と手順番号だけを表示し、Change は変更接続を強く示す。シナリオ切替で選択対象が経路から外れたら、選択と手順説明を解除する。番号を選ぶと動作と分岐条件を図の近くに表示する。実行シナリオがないモデルでは Execution モードを表示しない。初期状態でも構造と変更箇所の手掛かりを残す。

選択した node / edge には `is-selected` を付け、対応する輪郭・線幅・局所背景の CSS を必ず定義する。端点や直接関係する接続は `is-related`、その他は弱い表示にする。選択状態は hover が外れた後も続く。対象名、関係、条件、Code Lens が一回の選択で同時に切り替わり、予期せぬスクロールを起こさない。選択中の SVG と対応コード行に同じ selection accent を使う。キーボードフォーカスは選択状態と区別できる形で残す。JavaScript 無効時にも Map と必要な詳細を読めるようにする。

## Code Lens

関係を選ぶと、その関係を実装する短い抜粋を全幅 Code Dock に表示する。説明や source metadata を横の狭い列に押し込まず、コードへ主な面積を渡す。原則5〜20行を目安に前後文脈を最小にする。短い lens に `max-height` や縦方向 `overflow:auto` を指定しない。行は不自然に折り返さず、長い場合だけ lens 内で横スクロールさせる。コードの実効文字サイズは desktop 14〜16px、mobile 13〜15px、行間は1.5〜1.65を目安に確認する。行番号は独立した小さな gutter に置く。生成時に token 化した静的 HTML で keyword / type / function / literal / string / comment / member を控えめに区別する。syntax color はトークン種別、semantic cue は**なぜ今この行を見るか**を表す。対象行には選択 accent の背景と marker、変更行には `+` / `−` / `Δ` の gutter を付ける。二つの意味を同じ色へ押し込めない。Change mode でも選択対象の行と変更種別を読み取れるようにする。元ファイル・行位置を短く示す。根拠の列挙は別の Evidence に置く。

図中の関係と Code Lens の該当行を同時に示し、対応箇所を探す視線移動を減らす。補足は1〜2文で足りるか確認する。Code Lens を開くための追加クリックを要求しない。

## Visual QA

desktop の第一画面で主要 node と接続・変更点を指せるか、狭い画面で全体像とラベルが読めるか確認する。実際に Overview→node→edge→Execution→Change→Overview を操作し、Map の選択、対象名、Code Dock のコード行が一致し続けるか見る。desktop で代表的なコード行が頻繁な横スクロールなしに読める幅か、文字の実効サイズと行間が読みやすいか、説明と metadata がコード幅を奪っていないか、短い抜粋に内部縦スクロールがないか確認する。Focus 時の Code Lens が十分な視覚優先度を持ち、Map との対応に大きなスクロールを要しないかも見る。選択のたびに目が探し回る、ページが跳ぶ、戻る操作が増えるなら修正する。図の切れ、衝突、ページ全体の横溢れ、見出し階層、コントラスト、キーボードのフォーカス、print、reduced motion も確認する。数量が理解対象でない限り棒・円グラフは使わず、測定されていない数値を作らない。
