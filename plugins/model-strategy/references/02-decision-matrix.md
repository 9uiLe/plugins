# タスク分類 × モデル/effort 決定マトリックス

基本原則: **高価なモデルは「判断」に、安価なモデルは「作業量」に使う。**
メインセッション(高性能モデル)のコンテキストを汚さないこと自体がコスト削減になる(キャッシュ効率 + 高単価トークンの節約)。

## §1 決定マトリックス

| タスク種別 | 担当 | effort | 理由 |
| --- | --- | --- | --- |
| アーキテクチャ設計・技術選定 | メイン (Opus 4.8 / Fable 5) | high〜xhigh | 判断の質がコストを支配。やり直しが最も高くつく |
| 最難関の実装・大規模リファクタ | メイン | xhigh | 長期一貫性が必要。高 effort は往復を減らし総コスト減になりうる |
| 仕様が固まった実装 | **sonnet-implementer** サブエージェント | (medium 相当) | output 40% 減。仕様を全部渡せば品質差は小さい |
| コードレビュー・監査 | メイン (high) + 検証 fan-out は Sonnet | high | 発見はメイン、個別検証は安価に並列化 |
| コード探索・構成調査・grep 系 | **haiku-scout** / Explore エージェント | low | 結論だけ回収。output 80% 減 |
| Web リサーチ・情報収集 | Sonnet サブエージェント fan-out → 統合はメイン | medium | 収集は量、統合は判断 |
| ドキュメント整形・コミットメッセージ・定型変換 | **haiku-scout** または Haiku | low | 判断不要の作業量タスク |
| テスト実行・lint・ビルド確認 | サブエージェント (sonnet/haiku) | low | 結果の解釈だけメインに返す |
| 大量の機械的一括処理 (API 利用時) | Batches API | — | 50% off。対話不要なら最安 |

## §2 モデル選択の境界線

### メインセッションを Fable 5 にすべきか?

Fable 5 のコストは Opus 4.8 の約 2 倍(トークナイザは同一。`00-pricing.md` §1)。ただし判断はサブスク提供フェーズ(`00-pricing.md` §4)で変わる:

**同梱期間中(〜2026-07-07・週次上限の 50% キャップ)**
- 追加費用ゼロで使える一方、**週次クォータを他モデルより速く消費**し、キャップに達すると期限前でも使えなくなる
- → 50% 枠は「Fable 5 でしか差が出ないタスク」に集中投下する: アーキテクチャ設計・最難関のデバッグ/実装・大規模マイグレーションの計画
- 定型実装・探索・レビューの検証 fan-out は従来通り Opus/Sonnet/Haiku に流し、枠を温存する
- effort は `medium`〜`high` 起点(`01-effort-levels.md`: Fable 5 は low でも従来の xhigh 級)。`xhigh`/`max` 常用は枠の浪費
- セーフガードにより一部リクエストは **Opus 4.8 に自動フォールバック**される。Fable 前提のワークフローを組まない

**従量クレジット期(2026-07-08 以降、または Enterprise Standard)**
- credits は API 単価($10/$50)なので純粋なコスト判断に戻る。次の場合のみ Fable 5:
  - 長時間の自律実行(夜間ラン・大規模マイグレーション)で、失敗・やり直しのコストがモデル差額を上回る
  - Opus 4.8 で 2 回失敗したタスク(やり直し 2 回 > 差額)
- それ以外の日常開発は **Opus 4.8 (high) で十分**

### Sonnet に委譲できる実装の判定基準

以下を満たすなら sonnet-implementer に出す:

1. 仕様・受け入れ条件・対象ファイルが文章で書き切れる
2. アーキテクチャ上の新しい判断を含まない
3. 失敗してもレビューで検出できる(テストがある、diff が読める)

1 つでも欠けるならメインで実装するか、先にメインで仕様を固める。

### Haiku に落とせるタスクの判定基準

- 「正解が一意に決まる」または「結論の要約だけ欲しい」タスク
- 例: ファイル所在の特定、依存関係の列挙、ログの要約、定型文生成

## §3 委譲時の鉄則

- **仕様・制約・コンテキストは最初に全部渡す**。往復 1 回ごとにコンテキスト再送のコストがかかる
- 戻り値は「結論 + 根拠の要点」のみ要求する。生ログ・全文をメインに持ち帰らせない
- 並列化できる独立タスクは 1 メッセージで同時に投げる(壁時計時間も短縮)
